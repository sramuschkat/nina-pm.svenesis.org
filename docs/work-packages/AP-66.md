# AP-66 – Engine: frei gewordene Zeit neu vergeben, kein Anfahren bei Fortsetzung

**Release:** R6 · **Größe:** M · **Abhängigkeiten:** AP-13d, PR #302 (A-32 Fortsetzung) · **Menschliche Aufgaben:** H-13 (geänderte Soll-Pläne abnehmen)

## Ziel
Die kopflosen Rig-Läufe vom 07.10.2026 (`real-rig-newmoon`/`real-rig-fullmoon`, Plugin 0.4.18, Engine 0.17.0) zeigen je Nacht noch **4–5 Lücken von 10–25 min**. Zwei Ursachen liegen in der Engine:
1. **Frei gewordene Slots werden nicht neu angeboten.** Endet ein Ziel früher (Bedarf erfüllt, Höhe, Mond) oder wird ein Block kürzer, bleibt die Zeit als `idle_gap` leer (allocation.md §8.6 Nr. 7).
2. **Anfahren bei Fortsetzung:** Setzt die erste Einheit einer Neuplanung das Ziel auf der Montierung fort, plant die Engine trotzdem `slew_center` ein. `currentUnitId` wird nur validiert. Das Plugin überspringt den Slew zwar (`CanSkipSlew`, seit 0.4.18 mit Gutschrift), die geplante Zeit fehlt aber im Plan als Belichtung.

Vorbild für die Reihenfolge der Vergabe ist das Konzept aus Starfront 0.2.2 (README „What Auto-arrange does“, nur die Idee): eine Lücke geht
- zuerst an das Ziel, das gerade auf der Montierung ist (kein Anfahren),
- dann an das nächste Ziel,
- an ein neues Ziel nur, wenn sich das Anfahren lohnt (Rest nach Rüstkosten ≥ Mindestzeit bzw. ≥ eine Belichtung bei Fortsetzung).

## Liefern

### A – Frei gewordene Zeit neu vergeben (Walk/Paint)
- Entsteht beim Walk eine Lücke (`idle_gap`) von mindestens einem Slot, wird sie in dieser Reihenfolge vergeben:
  1. **an die Einheit des vorigen Blocks**, wenn sie noch Bedarf hat und in der Lücke abbildbar ist (gleiches Ziel → keine Rüstkosten, kein `slew_center`; Block wird verlängert),
  2. **an die Einheit des folgenden Blocks** (früher beginnen; Rüstkosten wie sonst),
  3. **an eine andere Einheit**, nur wenn Rest nach Rüstkosten ≥ ihre Mindestzeit.
- Unverändert bleiben:
  - Prioritäten und Fairness (A-10);
  - Mondregeln, Dunkelheit, Höhe;
  - Transits: keine Verschiebung des Transitfensters;
  - Flips: Fixkosten nur, wenn der Meridian noch bevorsteht (A-32/#302).
- Das 5-min-Raster bleibt (Entscheidung Sven 07.10.2026).

### B – Kein Anfahren bei Fortsetzung
- Ist die erste Einheit des Plans die fortgesetzte Einheit (`tonight.currentUnitId`, gleiche Bedingung wie A-32: vergangener Block dieser Einheit endet ≤ 300 s vor `startAtS`), entfällt `slew_center` am Blockbeginn. Die Zeit wird Belichtung.
- Die Rotation bleibt erhalten.
- Das Plugin braucht dafür keine Änderung: `CanSkipSlew` greift weiter, der Plan enthält nur keinen Slew mehr.

### C – Kompatibilität, Soll-Pläne, Parität
- Neue Abweichungen A-33 (Neuvergabe) und A-34 (kein Slew bei Fortsetzung) in `allocation.md` §10, mit Schaltern in `compat.ts`. Im Kompatibilitätsmodus (Orakel) aus.
- **Engine-Version** erhöhen (0.18.0).
- Soll-Pläne neu erzeugen. Jede Änderung im PR mit Begründung, die Abnahme durch Sven (H-13) ist Merge-Bedingung.
- Jint-Parität (`pnpm engine:bundle && pnpm engine:parity`), `engine:bench`, C#-Paritätstests grün.

## Nicht im Umfang
- 5-min-Raster aufheben.
- Gemessene Overheads (AP-65).
- Autofokus-Zeitpunkt an NINAs Timer angleichen.

## Entscheidungen (Sven, 07.10.2026)
1. Frei gewordene Zeit neu vergeben, Reihenfolge: Ziel auf der Montierung → nächstes Ziel → neues Ziel, wenn es sich lohnt.
2. Kein `slew_center` bei Fortsetzung desselben Ziels.
3. Das 5-min-Raster bleibt.
