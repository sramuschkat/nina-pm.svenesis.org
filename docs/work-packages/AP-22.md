# AP-22 – Mosaik-Panels im Editor (aus der Sternkarte)

**Release:** R2 · **Größe:** M · **Abhängigkeiten:** AP-21 · **Menschliche Aufgaben:** –

## Ziel
Mosaike werden in der Sternkarte entworfen und als Panels ins Projekt übernommen; die Planung der Panels existiert seit R1.

## Anforderungen
FA-PRJ-06, FA-FRM (Mosaik)

## Lesen (nur diese Abschnitte)
- FK 6.3, 6.4
- TK 7.2 (Projekte, Panels)
- specs/engine/geometry.md §2
- rules/ui.md
- specs/ui/components.md
- `CLAUDE.md`, `docs/rules/testing.md`; Abschnitt → Zeilen: `docs/concept/INDEX.md`

## Liefern
- Mosaik-Raster aus S-20 als Panels übernehmen – Panel-Mittelpunkte und Positionswinkel **ausschließlich** über die Engine-Funktionen aus `geometry.md` §2 (inverse gnomonische Projektion, exakte Felddrehung), keine eigene Näherung im Frontend
- Panel-Liste im Editor (Label, Koordinaten, Rotation, aktiv), Schalter „Panels getrennt planen“ je Projekt; der Scheduler plant Panels bereits seit R1 (AP-13b/c)
- **Entscheidungen Sven (25.09.2026):** „Panels getrennt planen“ bleibt die Rig-Einstellung (`rig.mosaic_panels_independent`, Scheduler seit R1, auch im NINA-Vertrag) – der Editor zeigt sie bei Mosaik-Projekten, Admins schalten sie dort um; kein Projektschalter (wäre eine Scheduler-Änderung). *Aktiv* je Panel über die additive Migration `0007_panel_aktiv` (`project_panel.enabled`, NULL = aktiv): Zeilen inaktiver Panels zählen wie deaktivierte Zeilen (Planung, NINA-Auslieferung, Fortschritt)

## Nicht im Umfang
- Scheduler-Änderungen
